# Контекст проекта ChatBot Shark

Этот файл хранит устойчивый контекст по репозиторию и ключевые решения. Его нужно обновлять при каждом существенном решении по структуре, рефакторингу, документации, сборке, тестам и подготовке проекта к публикации на GitHub.

Дата создания: 2026-04-23

## Исходная установка

В репозитории находятся 3 версии проекта, отражающие развитие учебного ChatBot Shark:

1. `Shark2_0_Cli` - CLI-версия, данные хранятся целиком в памяти на классах и указателях.
2. `shark3_0_Postgres` - CLI-версия, серверная часть хранит данные в PostgreSQL.
3. `Shark_3_0_Qt` - десктопная версия на Qt + PostgreSQL.

Каждая версия уже снабжена своим `README.md`.

## Глобальная цель

Оформить весь набор проектов как GitHub-репозиторий учебного проекта для демонстрации работодателям.

Ожидаемый результат:

1. Провести рефакторинг кода каждого подпроекта.
2. Привести форматирование к best practice для современного C++/CMake/Qt.
3. Улучшить документацию на уровне корня репозитория и каждого подпроекта.
4. Добавить недостающие инженерные артефакты, которые повышают оценку учебного проекта: инструкции сборки и запуска, архитектурные заметки, схемы, примеры конфигурации, тесты, CI, лицензия, `.gitignore`, возможно демо-скриншоты и roadmap.
5. Сохранить учебную ценность проекта: показать эволюцию от in-memory CLI к PostgreSQL и затем к Qt desktop.

## Рабочие принципы для следующих итераций

1. Не смешивать unrelated refactoring с изменениями документации, если это мешает проверке.
2. Сохранять историю развития проекта как достоинство, а не пытаться слить 3 версии в один безликий код.
3. Перед крупным рефакторингом сначала фиксировать цель и границы изменения в этом файле.
4. После принятия архитектурного или организационного решения добавлять запись в журнал решений.
5. Для публичного GitHub-репозитория избегать секретов, реальных паролей, приватных endpoint'ов и персональных конфигураций.

## Правила выполнения работ

1. Любые изменения выполняются только после явного разрешения владельца проекта.
2. Перед изменениями нужен план с точным перечнем затрагиваемых файлов.
3. Выполняется только утвержденный план.
4. Скрытые изменения и изменения вне утвержденного плана запрещены.
5. Попутный рефакторинг в процессе выполнения запрещен, если он не был явно включен в план.
6. Глубокий рефакторинг без отдельного согласования запрещен.
7. Нельзя менять структуру проекта, архитектуру, библиотеки, классы, методы и паттерны без отдельного согласования.

## Предварительные направления работ

1. Корневой уровень:

2. `Shark2_0_Cli`:

   - выделить учебные акценты: классы, указатели/smart pointers, in-memory модель, TCP клиент-сервер.

3. `shark3_0_Postgres`:
   - проверить слой доступа к PostgreSQL;
   - отделить пример конфигурации от реальных данных подключения;

   - проверить структуру Qt-клиента, серверной части и DTO;
